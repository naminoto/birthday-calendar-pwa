### iPhoneで旧ホーム画面名・アイコンが残る場合

manifestのname/short_name、apple-mobile-web-app-titleはYoribi、Apple Touch Iconは正式PNG 180pxです。SWは新しいPNGを含むシェルをキャッシュしますが、OSに追加済みのホーム画面名・アイコンの強制更新は行えません。公開版で確認したHTTP Cache-Controlはmax-age=600で、HTTPキャッシュとOSの保存済みアイコンは別です。[Appleの設定資料](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html)と[WebKitの説明](https://webkit.org/blog/13878/)は追加時の名称・アイコン指定を説明していますが、既存アイコンが更新時に必ず置き換わるとは保証していません。

安全な確認手順：①既存PWAからZIPを保存しFiles等で存在を確認 ②旧アイコンを残す ③Safariで同じ公開URLを開き、必要なら10分以上待って再読み込み ④共有→ホーム画面に追加でYoribiの名前と絵柄を確認（追加前にキャンセルも可能）⑤実際に追加した場合は新しい起動先の人物・画像を確認し、空なら保存済みZIPを検証・確認して復元。既存PWAとSafari／新しいPWAが同一データ領域とは限りません。確認できるまで旧アイコン・サイトデータを削除しないでください。削除や再追加を自動で促す機能はありません。

## データと更新

- `src/db.js` のIndexedDB `birthday-circle-local` は人物・画像・設定・通知を別storeに保存します。v1が人物・画像・設定、v2が通知追加、v3が既存人物内の固定記念日へ安定IDと新設定を付ける前方移行です。人物・画像・通知設定は削除せず、記念日なしの人物は0件のままです。以後もDB versionを上げ、`onupgradeneeded` で旧データを保持してください。
- 記念日は人物の`anniversaries[]`へ保存し、新規の任意記念日は`id`、`type: CUSTOM`、`title`、`month`、`day`、任意の`year`、`recurring`、`showAnniversary`、`notify`を持ちます。誕生日は既存の`type: BIRTHDAY`を維持します。旧固定種類も読み込めます。人物削除で記念日と通知をまとめて削除し、記念日変更時は対象通知だけ整理します。
- 表示言語は既存の設定storeに別キーで保存します。初期値は日本語で、設定画面からEnglishへ切り替えられます。人物名・メモ・カテゴリの内部値・利用者が入力した記念日名は翻訳・書き換えません。
- 人物と画像の保存・置換・削除は同一IndexedDBトランザクションです。画像は人物IDをキーに1枚だけ保持し、差し替えで旧画像を上書きします。
- `src/sw-template.js` はアプリシェルのみをキャッシュします。ビルド時にファイル内容からキャッシュ名を作り、新SWのactivate時には同じアプリ・同じサブパスの旧シェルキャッシュだけを削除します。IndexedDBには触れません。
- 新バージョンが待機すると「アップデートがあります」を表示します。「あとで」は現在の前面セッションだけ案内を閉じ、PWAを再び前面に出したときや次回起動時に**まだ待機中なら**再提示します。同じ前面セッション中には繰り返し表示しません。「更新する」なら待機SWへ切替を指示し、`controllerchange`後に**1回だけ**再読み込みします。別タブが先に更新した場合も編集中の画面を突然破棄しません。追加の更新確認はオンライン時に最大6時間に1回で、失敗しても現行版を維持します。全ての旧ページが閉じられると、ブラウザが待機中SWを自動で有効化する場合があります。その場合は次回起動時に更新案内は不要です。
- 設定には現在実行中のVersionと更新状態を常設します。ホームで「あとで」を押しても、待機中の更新は設定から適用できます。「更新を確認」は6時間制限とは別にその場でService Workerの確認を実行し、確認中・検出なし・オフライン・失敗を区別します。「検出なし」はその確認時の結果であり、常に最新版である保証ではありません。ホームと設定は同じ切替処理を使い、ブラウザ自身による待機SWの自動有効化も妨げません。
- アプリVersionは`package.json`の`version`を元に、設定画面・ZIP manifest・Service Workerへ共有します。キャッシュ名のハッシュは別の「ビルド内容識別子」です。公開時にVersion更新とREADME確認を行ってください。
- 「不要なアプリキャッシュを削除」は旧シェルキャッシュのみ対象で、現在利用中と更新待ちのシェル、IndexedDBを残します。ストレージ欄には人物数・画像数・画像Blob容量・アプリキャッシュ概算・取得可能な場合だけブラウザ推定のサイト総使用量・画像参照整合性を表示します。Safari等で総使用量を取得できない場合は「取得できません」と表示します。ブラウザ自身のキャッシュは操作しません。
- Webブラウザのサイトデータ削除、プライベートブラウズ、OSによるストレージ退避・削除では利用者データが失われる可能性があります。重要なデータは定期的にZIPへバックアップしてください。

カレンダーのカテゴリ・予定種類選択は表示だけを絞り込み、人物データは変更しません。初期値は両方「すべて」です。予定は丸いプロフィール画像（未登録・読み込み失敗時は名前の先頭文字）を主体に表示し、誕生日は🎂、その他の記念日は🎉を添えます。アイコンを押すと人物詳細が開きます。同じ人物の複数予定も別々に扱い、1日あたり最大1予定＋非表示の予定件数を表示します。「+件数」または日付を押すと省略分を含む全予定を確認できます。スマホではアイコン中心、広い画面では名前も併記します。カレンダーは読み込み済みの共有画像URLを利用し、月移動・絞り込みでIndexedDBの画像を再取得したりURLを増やしたりしません。

## カレンダーの日付から人物を登録

日付を押すと予定件数にかかわらず日付別一覧が開き、「この日に新しい人物を登録」から既存の人物フォームへ進めます。予定0件でも登録できます。選択した月日だけを誕生日の初期値にし、生年は空欄です。保存前に月日を変更できます。通常の人物追加には前回の日付を引き継ぎません。

保存後は入力した誕生日の月へ戻り、人物が隠れる場合だけカテゴリ・予定種類フィルターを「すべて」へ広げて登録結果を表示します。失敗時はフォームを残し、キャンセルでは保存しません。既存人物の「誕生日の日付を選ぶ」も利用でき、日付別一覧の専用ボタンで割り当てます。ドラッグでの誕生日設定と人物アイコンからの詳細表示は従来どおりです。

## カレンダーの移動・人物選択

日付セルはスマホ・PCとも7列の正方形です。人数が増えても高さは変えず、最大1予定と残件数を表示します。月による4〜6週の違いはそのままです。日付・「+件数」から全予定を確認できます。

カレンダーの予定アイコンはPCでドラッグ、スマホで約0.55秒長押ししてから移動できます。移動先の強調を確認して離すと、人物名・予定名・変更前後の日付を表示します。「変更する」で初めて既存の人物保存処理へ渡します。通常タップは人物詳細です。長押し前に指を動かすと通常スクロールに戻します。無効な場所・元の日付・キャンセル・画面離脱では保存せず、保存失敗時は元データと確認画面を保ちます。キーボードやドラッグできない環境では従来の人物編集を利用できます。

誕生日は生年・年齢表示を維持して月日だけ変更します。記念日はIDで識別してその1件だけを変更し、毎年型の起点年・周年表示・通知設定を保ちます。一度きりの記念日は移動先の年も日付として使います。別の月への移動は人物編集を使用してください。2/29の平年表示は既存どおり2/28です。同じ表示日へ戻しても保存済み2/29を2/28へ書き換えません。変更した予定の古い通知は既存処理で整理されます。

人物カード／カレンダー横の人物一覧は長押し、またはShift+Enterで誕生日設定の対象を選べます。選択中の人物を強調し、カレンダー上の専用案内から日付を選びます。「選択を解除」で終了します。長押し時の文字選択・呼び出しメニューの抑止は人物カードと予定アイコンに限定し、入力欄や通常説明文の選択は維持します。空状態は人物グリッドの全幅で横書き表示します。

`node scripts/browser-smoke.mjs`には0/1/2/10予定での正方形・高さ比較、Edgeの実マウス・タッチ入力が生成するPointer Events、確認前未保存・保存失敗・日英・空状態の検証を含みます。iPhone Safari/PWA固有の長押し・スクロールとの切替は実機でも再確認してください。IndexedDB v3とZIP v1は変更していません。公開後はrelease-smokeの公開URL指定に `--check-interactions=true` を追加すると、同じ操作検証を空の一時プロファイルで実行できます。実利用者データは使用しません。

## ZIPバックアップと復元

設定画面でZIPを書き出せます。`manifest.json` に形式Version、アプリVersion、作成日時、件数、ファイル一覧とSHA-256を記録し、`data.json` に人物・全記念日・URL・設定（言語を含む）・通知と既読状態、`images/` に管理画像を保存します。配列へ項目を追加しただけなので形式はv1のままです。旧v1 ZIPに新記念日項目がない場合は既定値（毎年、周年OFF、通知OFF）を付けて復元します。記念日自体がなければ0件です。旧v1 ZIPに言語項目がない場合は日本語を初期値とします。v0試作形式の `birthday:{month,day}` から `anniversaries[]` への変換基盤もあります。

復元はZIP容量・構造・Version・件数・チェックサム・人物/画像/通知の参照を**書き込み前**に確認してプレビューし、さらに確認ダイアログと「復元」の入力を経て実行します。4 storeを単一トランザクションで置き換え、失敗時は旧データを保ちます。復元後には画像の参照切れと孤児を確認します。復元前に現在データのZIPを書き出してください。

ZIPは暗号化されていません。メモや画像が含まれるので、安全な場所へ保管し、公開リポジトリには置かないでください。端末間のリアルタイム同期はありません。スマホ→PCなどの移行は、一方でZIPを書き出してもう一方で復元します。

### 別の端末へデータを移す

設定の「別の端末へデータを移す」で、スマホ→PC、PC→スマホ、スマホ→スマホ、PC→PCを選ぶと、端末別の手順が表示されます。専用の通信や同期機構ではなく、上記のZIP書き出し・検証・復元を共用します。

1. 移行元で「この端末のデータを書き出す」を押し、ファイルを保存する。
2. ファイルを移行先へ安全に渡す。ファイルは暗号化されていないため、公開場所へ置かない。
3. 移行先で同じYoribiの公開URLを開く。移行先の現在データを残したい場合は、先に同じ書き出しボタンで退避する。
4. 移行先で「受け取ったファイルを選ぶ」を押し、検証済みの内容と現在件数・置き換え後件数を確認する。
5. 置き換え確認と確認語の入力後、ファイルの内容で完全復元する。

これは**自動同期でもマージでもありません**。移行先の人物・画像・通知・設定は、移行元でファイルを作成した時点の状態に完全置換されます。移行元で削除した人物や、移行先にしかいない人物は移行先に残りません。以後の変更を移すには新しいファイルで手順を繰り返します。復元は全内容を検証してから4つのIndexedDB storeを単一トランザクションで置換します。ZIP形式v1とDB v3はこの案内機能では変更しません。

現在のZIP容量上限は128 MiBです。書き出し時にも上限を確認し、復元できない大きさのZIPを作らないようにしています。大量の画像を扱う場合は容量表示を確認してください。

## 公開前のプライバシー確認

配信対象は**`dist/` の16ファイル**（HTML、JS、CSS、manifest、Service Worker、アイコン、Zen Maru GothicのTTF3本・OFL・METADATA・SOURCE）だけです。`npm run build` は許可リスト、フォント原本のSHA-256と権利文書、秘密情報らしい文字列、絶対パス、manifest・アイコン・キャッシュ設定を監査し、疑わしい配布物があれば失敗します。親のSpring Bootソース、`.env`、DB、アップロード画像、ZIP、テスト成果物、`node_modules/` を配信しません。公開前にもう一度 `npm run build` と `npm run audit:dist` を実行してください。これは公開ファイルの検査であり、Git履歴全体の機密情報検査を保証するものではありません。

人物・誕生日・メモ・URL・画像・設定・通知は、閲覧中のブラウザのIndexedDB内にあります。外部SDK、analytics、CDN、外部フォント、画像自動取得、X API/OAuth通信はありません。配布HTMLには外部通信を制限するCSPがあります。アプリ本体の取得と更新ではPagesへ静的ファイルのリクエストが届き、IPアドレス等の通常のアクセス情報はホスティング側で扱われます。利用者がX・関連URLを明示的に開くと、そのリンク先へ移動します。ZIPを書き出してクラウド保存・共有すれば、その操作でデータは端末外へ出ます。ZIPは暗号化されません。

**GitHub Pagesのサブパスはデータの隔離境界ではありません。** `https://<owner>.github.io/a/` と `.../b/` は同一オリジンで、別アプリから同じIndexedDBを読める可能性があります。人物データを扱う試用では、そのホストに信頼しない別サイトを置かない専用GitHubアカウント、または専用カスタムドメインを推奨します。公開URLのホスト（オリジン）を後から変更するとIndexedDBは自動移行しません。変更前にZIPを保存し、新URLで復元してください。ブラウザのサイトデータ削除でも消えるため、定期バックアップが必要です。

## GitHub Pagesへのテスト公開（手動操作）

親のSpring Bootリポジトリ全体を公開せず、独立Gitリポジトリになっている**`local-pwa`だけ**をPWA専用リポジトリへ送ります。`.github/workflows/pages.yml` はこのリポジトリのルートにあり、`workflow_dispatch` の手動実行だけで、push時には自動公開しません。`npm ci` → `npm test` → `npm run build`（公開物監査を含む）→ `dist/` だけをPagesへ渡します。ソースリポジトリの内容と、実際にWeb配信される`dist/`は別です。公開リポジトリのソースとGit履歴も閲覧可能なので、ZIP、実利用者データ、`.env`、`node_modules/`、`dist/`、`test-artifacts/`はcommitしません。

利用者が行うGitHub操作：

1. `local-pwa`内でGitルートとcommit対象を確認する。GitHub FreeのPagesを使う場合は公開リポジトリが必要です。非公開リポジトリからPagesを作れても、Pagesサイト自体は一般公開されるので、テストURLも公開URLとして扱ってください。
2. 親のSpring Boot版を含めず、`local-pwa`の変更だけをcommit/pushする。`.gitignore`の除外と対象ファイル一覧を確認する。
3. 自分でpushした後、GitHubの **Settings → Pages → Build and deployment → Source: GitHub Actions** を選ぶ。
4. **Actions → Local PWA Pages preview → Run workflow** を自分で実行する。テストとビルドが成功したら表示されるPages URLを開く。以後の更新もpushだけでは公開されず、同じ手動実行が必要です。

Viteは `base: './'`、manifestの`id/start_url/scope`とService Workerも相対パスです。リポジトリ名が変わってもビルド時の固定パス調整は不要です。ただし、公開URL自体を変更した場合は上記のオリジンとZIP移行に注意してください。HTTPSのPages URLでなければ実機のService Worker/インストールを十分に検証できません。GitHubへのpushだけでは、この手動WorkflowによるPages公開は始まりません。

## iPhone / Android / PC 実機テスト

実機テストは公開HTTPS URLで行い、**テスト用の架空人物のみ**を登録してください。Safari/Chromeのプライベートモードは使いません。各端末で以下をチェックします。

- [ ] 公開URLを開き、画面・アイコン・CSSが表示され、再読み込みも成功する
- [ ] ホーム画面に追加し、ブラウザのタブではなく独立したアプリとして起動する
- [ ] 人物追加、誕生日登録、カテゴリ・メモ・関連URL編集、カレンダー・絞り込み・通知が動く
- [ ] カレンダーでカテゴリを切り替え、同じ日付の複数人物が選択カテゴリだけ表示される。月移動と「今月へ」も使える
- [ ] 人物へ名称自由入力の記念日を複数追加・編集・削除する。年なし/年あり・繰り返し・周年・通知ON/OFFを確認し、カレンダーの予定種類絞り込みと14日以内表示を試す
- [ ] 設定でEnglishへ切り替え、全画面・通知・人物編集・画像調整・ZIP復元文言が英語になり、再起動後も保持される
- [ ] 人物編集・検索・記念日などの入力欄をタップしても勝手に画面が拡大されず、通常のピンチズームは使える
- [ ] 写真選択直後に黒い画面にならず、指で位置移動・ピンチ/スライダー拡大・決定・キャンセルができる
- [ ] JPEG/PNGと、対応iPhoneではHEIC・縦向き/横向きのEXIF付き写真を試し、向きと丸型表示を確認する
- [ ] プロフィール画像を登録・変更・削除し、容量表示と画像件数が正しい
- [ ] Xプロフィールを押した**ときだけ**外部ページが開く
- [ ] アプリを完全に閉じて再起動しても、人物・誕生日・画像・設定・既読状態が残る
- [ ] 一度オンラインで開いた後、機内モードで起動・再読み込みし、人物を見られる
- [ ] 設定からZIPを書き出し、端末のFiles/ファイル等に保存し、ZIP内のmanifest・画像を確認する
- [ ] ZIP書き出し後にテスト人物を変更し、ZIPを選んで内容プレビュー・確認入力後に復元する。元データへ戻る
- [ ] ZIPをPCへ移し、PC版の設定から復元できる。逆方向も試す。転送先がクラウドなら自分の判断で使う
- [ ] 「別の端末へデータを移す」で端末の組み合わせを選び、移行先を先に退避してから完全復元する。移行元で編集・削除した人物と、移行先にしかいない人物の結果を確認する
- [ ] 新ビルド公開後、「アップデートがあります」を確認。「あとで」で継続利用し、再起動後に「更新する」を選ぶ。旧v2からv3への移行後も人物・画像・通知設定・言語が残り、旧アプリキャッシュだけ消える
- [ ] 設定のアプリVersionと更新状態を確認し、「更新を確認」を押す。更新が待機中なら設定からも「アップデートする」を試す。「あとで」でホーム案内を閉じても設定には更新が表示されることを確認する
- [ ] 更新前に「テスト太郎」と画像をZIPへバックアップし、更新後も同じ人物・画像が残る（この端末に既にあるデータを先に消さない）
- [ ] ストレージ表示と旧キャッシュ整理を確認し、人物・画像・記念日が消えない

iPhone：Safariの共有ボタン→「ホーム画面に追加」→「Webアプリとして開く」を有効にして追加します。iOSのバージョンで文言やZIP保存先の表示が異なります。ZIPダウンロードはSafari/ホーム画面アプリで保存先を確認し、見つからない場合はSafariで同じURLを開いて再試行してください。写真アクセスとFilesからのZIP選択も実機で確認が必要です。

Android：Chromeのメニュー→「アプリをインストール」または「ホーム画面に追加」。ZIPはダウンロード/Files等で所在を確認してから復元ファイル選択で開きます。PCではChrome/Edge等から同じURLを開いて試します。iPhone・AndroidのインストールUI、OSの容量回収、ZIP保存動作はローカルEdge試験だけでは保証できません。
