# v1.4.3候補：独立テスト版とiPhone実機確認

この文書はv1.4.3正式公開前に使用した独立テスト版の準備・実機確認記録です。正式版v1.4.3は2026年11月4日に公開し、独立テスト版は引き続き`yoribi-preview/yoribi-test`と`https://yoribi-preview.github.io/yoribi-test/`へ分離します。

## 分離とVersion

- 正式版：`https://naminoto.github.io/birthday-calendar-pwa/`、Version 1.4.3。
- テスト版：別originの`https://yoribi-preview.github.io/yoribi-test/`。IndexedDB、localStorage、Cache Storage、Service Workerは正式版originと共有しない。
- Vite `base`、manifestの`id/start_url/scope`は相対`./`。Service Workerは配置された`/yoribi-test/`以下だけをscopeにする。
- ローカル正式候補の`package.json`は1.4.3。テスト成果物だけに`yoribi-preview-version=1.4.3-candidate`を追加し、設定Version、バックアップmanifest、SW Versionを候補番号にする。
- 画面上部、ブラウザタイトル、ホーム画面名にテスト版／v1.4.3候補を表示する。正式版の更新履歴はv1.4.3の公開日を2026-11-04として表示する。

## ローカル準備から承認直前まで

1. `npm test`、`npm run build`、`npm audit`、ブラウザ回帰、正式版v1.4.2からのSW更新・DB保持・旧ZIP互換試験を完了する。
2. 通常候補は`node scripts/prepare-iphone-preview.mjs`を実行する。Git除外された新規`test-artifacts/iphone-preview-<UUID>/`へ、診断なしの監査済み`dist`コピーとテスト用HTML／manifest／SW、手動Workflow、`PREVIEW.json`だけを生成する。
3. 診断UIを含む独立テスト版が必要な場合だけ、`npm run build:preview-diagnostics`後に`node scripts/prepare-iphone-preview.mjs --avatar-diagnostics`を実行する。通常の正式buildと通常候補には診断コードを含めない。
4. `node scripts/audit-iphone-preview.mjs <生成先>`で全ファイル、SHA-256、候補表示、相対scope、正式owner拒否、手動Workflow、秘密情報・利用者データなしを確認する。
5. `node scripts/release-smoke.mjs --serve-dist=<生成先>/site --expected-version=1.4.3-candidate --check-preview=true --check-lifecycle=true --check-backup-security=true`で、候補Version、暗号化、削除、オフラインを使い捨てlocalhostプロファイルで確認する。
6. 既存テストrepo checkoutのGitルート、clean状態、remoteが`https://github.com/yoribi-preview/yoribi-test.git`、remote mainが期待SHAであることを確認する。
6. 新しい準備一式をテストrepo checkoutへ反映し、`git diff`と再監査を行う。ここで停止する。commit／push／Actions実行／Pages公開はまだ行わない。

## iPhone実機チェックリスト

実名・実写真・正式版バックアップを使わず、テスト専用の架空データだけを使用する。問題が起きてもSafariサイトデータやPWAを消さず、Version、iOS、機種、Safari／ホーム画面版、手順と画面を記録する。

### 基本動作

1. SafariでテストURLのhostが`yoribi-preview.github.io`であることと「テスト版 / v1.4.3候補」表示を確認する。
2. iOS初回案内を確認し、共有メニューから「Yoribi テスト」をホーム画面へ追加する。
3. ホーム画面版で架空の人物、画像、誕生日、複数記念日、メモ、通知設定を登録する。
4. 終了・再起動後も人物・画像・記念日・設定が残ることを確認する。
5. 初回取得完了後に機内モードで再起動し、画像・フォント・更新履歴を含め表示できることを確認する。

### 画像と人物編集

6. iPhoneで撮影した高解像度の縦長・横長・回転情報付き写真と、可能ならHEIC/HEIFを選ぶ。
7. ドラッグ、ピンチ、スライダーでトリミング位置と倍率を変更する。
8. ×で閉じ、ファイル選択と未確定プレビューが残らないことを確認する。
   - 写真ピッカー内で1枚選択し、その写真のチェックを外して「0枚の写真を選択中」に戻してから青いチェックを押す。トリミング画面へ進まず、人物フォームの既存画像が維持されることを確認する。
   - 写真選択後、ピッカー自体をキャンセルする。しばらく待っても選択解除した写真でトリミングが遅れて開かないことを確認する。
   - 取消直後に別の写真を選び、新しい写真だけがトリミング画面に表示されることを確認する。
9. 再選択して✓、人物保存、再起動後の512px画像表示を確認する。
10. 既存人物で別画像を選び×。元画像が維持されることを確認する。
11. 新規・編集画面を開いた直後に名前欄へフォーカスせず、キーボードが出ないことを確認する。名前欄をタップすれば入力できることも確認する。

### バックアップ

12. 12文字以上のテスト専用パスワードで`.yoribi`を作成し、「ファイル」アプリへ保存する。
13. 架空データを変更後、正しいパスワードでプレビューし、完全置換の警告を確認して復元する。
14. 誤パスワードと破損コピーを選び、復元されず変更後の既存データが保持されることを確認する。
15. v1.4.2で作成した架空データだけの旧ZIPがある場合は、新テスト版で読み込めることを確認する。正式利用者のZIPは使わない。
16. iPhoneのパスワードマネージャーで保存・自動入力できるか確認する。利用できない場合は環境依存の未対応として記録する。

#### Password AutoFillと入力内容プレビュー（iOS WebKit実機ゲート）

この項目はChromiumの疑似イベントでは代替できない。Safariとホーム画面PWAの両方で、テスト専用の架空パスワードだけを使用する。実行時はiOS Version、機種、起動方式、黄色背景の有無、フォーカス中の欄を記録する。

1. バックアップ作成画面を開き、iPhoneのパスワード自動入力でパスワード欄と確認欄を入力する。
2. 両欄が薄い黄色のAutoFill表示であることを確認する。
3. パスワード欄をタップし、パスワード欄だけ黄色表示が解除された状態を作る。
4. キーボードを開いたまま「入力内容を確認」を押す。
5. 2つの入力欄は伏せ字・`type=password`のままで、別の編集不可領域に①②の現在値が正しいラベル付きで表示されることを目視する。
6. 「確認表示を閉じる」を押し、別領域の平文が消えることを確認する。
7. 確認欄をタップして同じ操作を行い、①→②と②→①の両方向を確認する。
8. 表示／非表示を5回以上繰り返し、キーボード、フォーカス、入力値、カーソル位置、スクロール位置が維持されることを確認する。
9. 手動入力、AutoFillのみ、AutoFill後に片方を手編集、空欄の各状態で繰り返す。
10. 確認表示を開いたまま入力値を変更し、別領域だけが現在値へ更新されることを確認する。
11. 復元画面でもAutoFill後の別領域表示とキーボード維持を確認する。
12. 確認表示中にSafari／PWAを背景へ移し、戻った時に平文表示が閉じていることを確認する。

別領域の値が①②で混ざる、入力欄自体の伏せ字・黄色いAutoFill状態が変わる、平文が閉じた後もDOMに残る、またはキーボードが閉じる場合は未解決として公開ゲートを不合格にする。SafariのPassword AutoFill状態とネイティブ入力描画はWebページの自動テストから制御・観測できないため、Chromiumの模擬入力だけを実機成功の根拠にしない。

### 更新履歴と保存領域

17. 設定の更新履歴が日英・ライト／ダーク・オフラインで開け、先頭のv1.4.3が2026-11-04、v1.4.2以前の公開日が維持されていることを確認する。
18. Safari側で登録した架空データがホーム画面側へ自動同期されない場合、案内どおりテスト用バックアップで移行できることを確認する。
19. 正式版アイコンを開き、正式版の人物・画像が保持され、Version 1.4.3へ更新されていることを確認する。テストデータを正式版へ復元しない。

### データ削除（必ず最後）

20. テスト用`.yoribi`がFilesに存在することを確認する。
21. データ削除を一度キャンセルし、全データが残ることを確認する。
22. 他のテスト版タブ／画面がある状態では削除を拒否することを確認し、閉じる。
23. 確認を完了して削除し、人物・画像・通知・設定の削除結果を確認する。
24. 再起動して古いデータが復活しないこと、利用終了・アンインストール案内が表示されることを確認する。

削除後もFilesのバックアップとパスワードマネージャーの内容はアプリ管理外なので別途扱う。正式版ではデータ削除試験を行わない。
