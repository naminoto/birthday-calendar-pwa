# v1.4.3候補：ローカルセキュリティ改善

後続の暗号化バックアップ・利用終了機能もローカルで追加済みです。[現行の暗号化・削除仕様](encrypted-backup-and-exit.md)を参照してください。以下の「暗号化を追加しない」等は先行のZIP安全性修正時点の記録で、新しい書き出しは`.yoribi`暗号化形式を使用します。内部ZIP v1と旧ZIP読込は維持します。

正式公開はv1.4.2のまま。候補のpackage Versionも今回は1.4.2を維持し、番号変更・commit・push・deployは行わない。DB v3／ZIP形式v1／公開URL／SW scope／テスト版／親Spring Boot版は不変。

## ZIP

- src/zip-reader.jsで中央ディレクトリとローカルヘッダーを展開前に全件確認。許可名はmanifest.json、data.json、images/UUID.binのみ。重複、名前不一致、暗号化、symlink、多disk、ZIP64、SFX／重なり／隠しentry、非対応方式は拒否。
- input128 MiB、実展開合計160 MiB、JSON各8 MiB、画像各2 MiB、2000entryの上限。1件でも違反なら全体を拒否し、filterで黙って落とさない。STOREは圧縮長＝展開長を要求。実長・合計・CRCを読み込んだ後にも確認。
- DEFLATEはnative DecompressionStream('deflate-raw')へ1 KiBずつ供給し、backpressureを使って実出力量を監視。宣言量を超えた時点でreaderをcancelする。entry間でUIへ制御を返し、複数ファイルを同時展開しない。
- 公式v1.4.2が作るZIPはSTOREなので、圧縮stream未対応のブラウザでも読める。第三者が再圧縮したZIPはnative raw-deflate対応が必要で、非対応時は安全側へ拒否する。未対応環境を推測した同期ライブラリへの無制限fallbackはしない。
- 書き出しにも同じディレクトリ検査を適用し、自分が容量制限を超えたZIPを生成しない。署名・暗号化は追加しない。SHAは真正性保証ではない。

## 画像と復元

- images.jsのvalidateBackupImageでPNG／JPEG／WebPの実シグネチャ・宣言寸法・容量を確認後、ブラウザで完全デコード。画素数16,777,216・辺長4096まで。既存の通常保存画像（最大512px）は再圧縮・変更せず保持。
- PNGはdecoderが破損を補修するケースがあったため、全chunkの境界・CRC・IEND・IDATも検証。アニメーションPNG／WebPは通常の保存形式ではないため受け付けない。
- デコードを順次行い、bitmapをclose、fallback Object URLをrevokeする。Nodeのunitには実PNGだけを許可するtest専用shimを使い、JPEG／WebP・本当の破損拒否はEdgeの実decoderで検証する。アプリにshimや新しい外部画像ライブラリは入れない。
- 検証完了前はDB書換えなし。復元は全4storeを単一transactionで置換し、件数確認もcommit前。同期例外・abort・件数不一致は全体rollback。成功commit後の別DB読取を復元結果判定に使わない。
- ZIP検証／復元中は再選択・二重送信を抑止。確認キャンセルは非破壊。commit後に表示更新だけが失敗した場合は「復元済み／再起動」を伝え、データが元に戻ったと誤案内しない。
